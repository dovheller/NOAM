# אפיון: איחוד מכשירים ומקורות — "תיק אחד, הרבה מקורות"

> סטטוס: טיוטה לאישור דב ונועם · חבילות עבודה: WP13–WP15 ב-`ROADMAP.md`
> מקורות לבחירת הכלים: `docs/REPO_CANDIDATES.md`

## 0. הבעיה

לקוח אמיתי לא מגיע עם טלפון אחד תקין. הוא מגיע עם:
- ארבעה מכשירים: הטלפון הנוכחי, טלפון קודם עם מסך שבור, טאבלט, וכרטיס SD שנשלף ממכשיר מת.
- תיקיית WhatsApp בכל אחד מהם: `WhatsApp Images`, `WhatsApp Video`, `Voice Notes`, `Documents`, `Sent`, וגם `Databases/msgstore.db.crypt15` ו-`Backups/`.
- קובצי ZIP ישנים (ייצוא Google Takeout, גיבוי שמישהו עשה פעם), ותיקיות שהועתקו ידנית למחשב.
- אותה תמונה ב-5 עותקים: המקור מהמצלמה, עותק דחוס שנשלח ב-WhatsApp, עותק ב-`Sent`, עותק בכרטיס SD, עותק ב-ZIP.

הלקוח רוצה **תיקייה אחת מסודרת**, בלי כפילויות, שבה הוא מוצא כל דבר, ושום דבר לא הלך לאיבוד.

## 1. עקרונות

1. **שום דבר לא נמחק ולא נזרק.** איחוד = סידור והפניה, לא מחיקה. כפילות מזוהה נשמרת פעם אחת, וכל המקומות שבהם הייתה נרשמים.
2. **כל קובץ יודע מאיפה בא.** לכל קובץ בתיקייה המאוחדת יש רשימת מוצא: מכשיר, נתיב מקורי, תאריך. הרשימה נשארת אצל הלקוח בלבד.
3. **המכונה מסדרת, האדם לא רואה.** המיון (תאריך מ-EXIF, זיהוי סוג, השוואת תמונות) רץ אוטומטית. המפעיל רואה ספירות: "4 מכשירים · 11,382 קבצים · 3,120 כפילויות זהות · 412 כמעט-זהות". עיקרון 1 ב-`CLAUDE.md` נשמר.
4. **כפילות ודאית ≠ כפילות משוערת.** זהה בבתים (SHA-256 זהה) → מאוחד אוטומטית. "כמעט זהה" (אותה תמונה בגודל אחר) → **מסומן** ללקוח, לא מאוחד לבד.
5. **אפשר לבטל.** הסידור הוא שכבת הפניות מעל הקבצים שהועתקו ואומתו (WP3). אם הלקוח לא אוהב את הסידור — מפיקים סידור אחר, בלי להעתיק שוב מהמכשירים.

## 2. מכשירים תקולים — מה אפשר באמת

| מצב המכשיר | איך קוראים ממנו | כבר קיים בקוד? |
|---|---|---|
| חי, מסך תקין | MTP | ✓ WP2 |
| כרטיס SD שנשלף (גם ממכשיר מת) | קורא כרטיסים → mass storage | ✓ WP2 |
| מסך שבור, מגע עובד חלקית / לא | עכבר OTG או HDMI/DeX כדי לפתוח נעילה ולבחור "העברת קבצים", ואז MTP | תפעולי (מסלול ב' באפיון WhatsApp §4) |
| מסך שבור, USB debugging הופעל בעבר | `scrcpy` לשליטה, ואז MTP | תפעולי |
| מסך שבור, נעול, בלי debugging | **אין גישה.** אנדרואיד דורש פתיחת נעילה לפני MTP | — |
| לא נדלק | מעבדה חיצונית (ראו אפיון WhatsApp §5.2) | — |
| גיבוי שכבר קיים: ZIP, Takeout, תיקייה במחשב, דיסק ישן | **מקור מסוג ארכיון/תיקייה** | ✗ — WP13 |

**מה הלקוח מקבל בכתב לפני תשלום:** איזה מכשיר נקרא, איזה לא ולמה. מכשיר שלא נקרא מופיע בדוח כ"לא נגיש", עם הסיבה.

## 3. ארכיטקטורה

```
מקורות (Source)            העתקה ואימות (WP3)          איחוד (WP14–15)
──────────────            ───────────────────          ────────────────
טלפון 1  (MTP)    ─┐
טלפון 2  (SD)     ─┤      לכל מקור: תיקייה גולמית       אינדקס אחד לתיק:
טאבלט   (MTP)     ─┼──▶   raw/<מכשיר>/…  + SHA-256  ──▶  sha256 → קובץ אחד
backup.zip (ארכיון) ─┤      (בלי לשנות שמות/מבנה)         + רשימת מוצאים
Takeout/ (תיקייה) ─┘                                     + סיווג + תאריך
                                                             │
                                                             ▼
                                                   תצוגה מסודרת (הפניות):
                                                   מסודר/2024/04 תמונות/…
                                                   מסודר/WhatsApp/קולי/…
                                                   מסודר/מסמכים/…
```

- **שלב 1 — גולמי, לכל מקור בנפרד.** WP3 כמו שהוא: כל מכשיר מועתק ל-`raw/<device_id>/` עם המבנה המקורי. זה העותק "המשפטי", המאומת.
- **שלב 2 — אינדקס.** עובר על כל `raw/`, מקבץ לפי SHA-256 (כבר מחושב ב-WP3, אין קריאה נוספת), מוסיף סוג אמיתי, תאריך ומוצא.
- **שלב 3 — תצוגה מסודרת.** תיקיית `מסודר/` שבנויה מ-hard links לקבצים ב-`raw/` (על exFAT, שאין בו hard links — עותק אחד לכל קובץ ייחודי, והכפילויות לא מועתקות שוב). קובץ ייחודי מופיע פעם אחת.

## 4. זיהוי

| מה | איך | כלי (ראו REPO_CANDIDATES) |
|---|---|---|
| כפילות ודאית | SHA-256 זהה | כבר במניפסט של WP3 |
| סוג אמיתי | חתימת הקובץ (magic bytes), לא הסיומת. `.jpg` שהוא בעצם וידאו, קובץ בלי סיומת | `filetype` (MIT) |
| תאריך צילום | EXIF/QuickTime → שם קובץ (`IMG-20240412-WA0007`, `PXL_20240412_…`, `Screenshot_20240412-…`) → תאריך שינוי | `exiftool` כתהליך משנה; תבניות שם — טבלה שלנו |
| שייכות ל-WhatsApp | נתיב: `WhatsApp/Media/WhatsApp Images|Video|Audio|Voice Notes|Documents|Animated Gifs|Stickers`, `Sent/`, `Private/`; גם הנתיב החדש `Android/media/com.whatsapp/…` | טבלה שלנו |
| גיבוי WhatsApp | `msgstore*.db.crypt12/14/15`, `wa.db*` | מועבר לשכבה 2 כ"נמצא גיבוי" — לא מפוענח בשכבה 1 |
| ארכיון | ZIP, 7z, TAR, RAR → נפתח כמקור משנה (קריאה בלבד, בזרם) | `libarchive-c` (CC0) |
| כמעט כפילות בתמונות | גיבוב תפיסתי (pHash/dHash). אותה תמונה במקור ובעותק הדחוס של WhatsApp | `imagehash` (BSD-2) |
| כמעט כפילות בווידאו | דגימת פריימים + גיבוב | `czkawka_cli` (MIT) כתהליך משנה, בשלב מאוחר |
| קובץ פגום | פענוח נכשל (תמונה שלא נפתחת, ZIP שבור) | `czkawka_cli` / Pillow |

## 5. התצוגה המסודרת — ברירת מחדל (לאישור)

```
מסודר/
  תמונות/2024/2024-04/        ← מצלמה + WhatsApp, לפי תאריך צילום
  וידאו/2024/2024-04/
  WhatsApp/
    הודעות קוליות/2024/
    מסמכים/
    מדבקות וגיפים/            ← מקופל, לא מעניין את רוב הלקוחות
  מסמכים/
  אודיו/
  אחר/
  _כמעט_כפולים/                ← זוגות לבדיקת הלקוח, לא נמחק כלום
  _לא_מזוהה/
מוצא.html                     ← אינדקס ללקוח: לכל קובץ — מאיפה הגיע, כל העותקים
raw/<מכשיר>/…                  ← העותק המאומת המקורי
```

- **מקור מנצח את העותק:** כשתמונה מהמצלמה והעותק הדחוס שלה מ-WhatsApp הם כמעט-כפולים, המקור (רזולוציה גבוהה) נכנס ל-`תמונות/`, והעותק נרשם במוצא ומופיע ב-`_כמעט_כפולים/`.
- **שם קובץ:** נשמר השם המקורי. התנגשות שמות → סיומת `-2`, `-3`.

## 7. קריטריוני קבלה

1. ארבעה מקורות מסוגים שונים (MTP, SD, ZIP, תיקייה) בתיק אחד, עם `raw/` מאומת לכל אחד.
2. כל קובץ ייחודי מופיע **פעם אחת** ב-`מסודר/`; סכום הייחודיים + כפילויות = סכום כל המקורות. אף קובץ לא נעלם (בדיקה אוטומטית).
3. תמונה ועותק ה-WhatsApp הדחוס שלה מזוהים כזוג כמעט-כפול, והמקור הוא זה שב-`תמונות/`.
4. ZIP בתוך ZIP נפתח (עומק מוגבל ל-3), ARCHIVE שבור מדווח ולא עוצר את התיק.
5. `מוצא.html` נפתח בכל דפדפן, בעברית, עם חיפוש.
6. אפשר להפיק את `מסודר/` מחדש מ-`raw/` בלי לחבר שוב מכשירים.
7. המפעיל לא רואה שם קובץ אחד בשום שלב (בדיקת WP6 מורחבת).

## 8. פתוח להחלטה

1. **הכללה בשירות:** איחוד הוא שירות נפרד (מחיר נפרד), או חלק מ"גיבוי" כשמגיעים יותר ממכשיר אחד?
2. **מבנה `מסודר/`:** לפי תאריך (כמו למעלה) או לפי מכשיר ואז תאריך?
3. **כמעט-כפולים:** להשאיר רק ב-`_כמעט_כפולים/` לבדיקה, או גם להציע ללקוח במסך "בחר מה להשאיר" (מסך טאבלט נוסף)?
4. **מדיה של WhatsApp ממקורות שונים:** אותה תמונה שנשלחה לקבוצה ונשמרה בשני טלפונים — SHA-256 זהה, מאוחד אוטומטית. אישור?
